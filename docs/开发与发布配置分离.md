# 开发配置与发布版本的区分

本文说明 Aegis 的**本地开发配置**与**发布给用户的干净版本**如何分离，以及发布前的安全检查如何执行。

---

## 一、两类数据的本质区别

| 类别 | 位置 | 是否进 Git | 是否进安装包 | 说明 |
|---|---|---|---|---|
| **源码** | 仓库目录 | ✅ 是 | ✅ 是 | `apps/` `static/` `templates/` `desktop/` `main.py` 等 |
| **默认配置** | `config/config.json` | ✅ 是 | ✅ 是 | 不含任何密钥的出厂默认值（DeepSeek 为首选） |
| **配置模板** | `.env.example` | ✅ 是 | ❌ 否 | 只有变量名，`API_KEY=` 全为空 |
| **本地密钥配置** | `.env` | ❌ **否** | ❌ **否** | 你自己填的 API Key、数据库密码 |
| **用户运行配置** | `%APPDATA%\Aegis\config.user.json` | ❌ **否** | ❌ **否** | 界面里改的设置 |
| **用户数据库** | `%APPDATA%\Aegis\aegis.db` | ❌ **否** | ❌ **否** | 会话、消息、记忆 |
| **密钥库** | 系统凭据管理器（keyring） | ❌ **否** | ❌ **否** | API Key 实际存放处 |
| **构建产物** | `dist/` `build/` `.venv-build/` `desktop/Output/` | ❌ **否** | ❌ 否 | 本地生成 |

**核心原则**：仓库里只有「源码 + 无密钥的默认值」，你的密钥与运行数据永远留在本机。

---

## 二、运行数据为什么不进仓库

程序**不写安装目录**，所有用户数据统一在：

```
%APPDATA%\Aegis\
├── aegis.db              会话 / 消息 / 记忆
├── config.user.json      界面里改的配置
├── keys.index.json       密钥引用（key_ref，非明文）
├── secrets.enc           加密的密钥库
├── logs\                 运行日志
└── run\                  单实例锁等运行时文件
```

因此即使有人把整个 `Aiagent/` 目录拷走，里面也**没有你的 API Key** —— 密钥存在 Windows 凭据管理器里，只在这台机器上有效。

## 三、发布前的安全检查

### 自动执行（打包时）

`desktop/build.bat` 的**步骤 3** 会调用 `prepublish_check.py`，发现问题立即以非零退出码**中止构建**：

```
[3/5] 发布前安全校验（密钥 / 敏感文件）
  [OK] 已跟踪文件 无敏感文件
  [OK] 已跟踪文件 未发现真实密钥
  [OK] 工作区 无敏感文件
  [OK] 工作区 未发现真实密钥
安全校验通过，继续构建
```

### 手动执行

```bash
python prepublish_check.py                # 全量检查
python prepublish_check.py --staged       # 只查暂存区（提交前）
python prepublish_check.py --dist         # 额外检查安装包洁净度
```

发现问题时以退出码 `1` 结束，可直接串进 CI：

```bash
python prepublish_check.py || exit 1
git add -A && python prepublish_check.py --staged || exit 1
git commit -m "..."
```

### 检查什么

| 类别 | 具体内容 |
|---|---|
| **敏感文件** | `.env`、`*.db`、`config.user.json`、`secrets.enc`、`keys.index.json`、`id_rsa*`、`*.pem`、`*.key`、构建目录… |
| **密钥形态** | OpenAI（`sk-…`）、Anthropic（`sk-ant-…`）、Google（`AIza…`）、AWS（`AKIA…`）、GitHub（`ghp_…`）、Slack（`xox*-`）、智谱、DeepSeek |
| **赋值形式** | `api_key = "…"`、`"token": "…"`、`password = "…"`（占位值与掩码已豁免） |

### 校验器自身有测试

一个从不报错的校验器等于没有校验器。`tests/test_prepublish_check.py` 用「故意埋雷」验证它**真能抓到** OpenAI / Google / AWS / GitHub / Slack 各类密钥，同时**不误报** `.env.example`、空值、`sk-...` 掩码、测试桩等正常内容：

```bash
python tests/test_prepublish_check.py     # 36 断言
```

## 四、安装包为什么是干净的

### 1. `build.spec` 白名单闸门

打包只允许三类目录进包：`templates/` `static/` `config/`。且每个文件都要过**扩展名白名单**（`.html` `.js` `.css` `.json` `.md` …），并有**文件名黑名单**（`.env`、`.db`、`config.user.json`…）。

违反即中止：

```
[build.spec] 洁净度检查未通过，以下文件不应进入安装包：
  static/.env（本地数据/密钥）
请移除这些文件，或修正本白名单。安装包必须是全新未配置版本。
```

这样即使有人把 `.env` 拷进 `static/`，打包会直接失败而不是悄悄发布出去。

### 2. 用户数据在包外

程序启动时自动在 `%APPDATA%\Aegis\` 建库建配置，**安装目录只读**。安装包不含任何 `.db` / `config.user.json` / 密钥。

### 3. 首次启动是干净的

新用户装完后：
- 数据库为空（自动建表）
- 配置为 `config.json` 的出厂默认值（DeepSeek 首选）
- 密钥库为空，需在首启向导里填自己的 API Key

## 五、开发者本地配置的正确做法

```bash
# 首次
copy .env.example .env          # 然后填入自己的 Key

# 之后正常用 git
git add .
git commit -m "..."
```

`.env` 已被 `.gitignore` 排除，**不会被提交**。想确认：

```bash
git check-ignore -v .env        # 应显示 .gitignore 的命中规则
git status --porcelain | grep '\.env'   # 应无输出
```

### 如果 `.env` 不慎被提交过

```bash
git rm --cached .env            # 从索引移除，保留本地文件
echo '.env' >> .gitignore
git commit -m "chore: 停止跟踪本地密钥配置"
```

⚠️ 这**只解决后续提交**。已经推送的历史里仍然存在密钥，必须：
1. 去服务商后台**吊销并轮换**该密钥
2. 用 `git filter-repo` 或 BFG 清理历史后强推

## 六、推送前的检查清单

```bash
python prepublish_check.py --staged   # 1. 密钥/敏感文件
python tests/test_prepublish_check.py # 2. 校验器自测（36 断言）
python -m pytest tests/ -q            # 3. 后端测试
git status --porcelain                # 4. 确认无意外文件
```

全部通过后再 `git push`。

# 大模型配置指南

本文档说明如何在不花一分钱的前提下让 Aegis 恢复完整对话能力。

系统采用**多服务商自动降级**架构：按优先级依次尝试各个模型服务，
第一个可用即生效；全部不可用时自动切换到内置的本地应答模式，界面不会报错。

---

## 一、最快上手（30 秒）

推荐用**智谱 GLM-4-Flash**，官方标注永久免费、不限 Token、并发 30。

1. 打开 <https://open.bigmodel.cn> 注册并完成实名认证
2. 进入 <https://open.bigmodel.cn/usercenter/apikeys> 创建 API Key
3. 设置环境变量后启动应用：

```bash
# Windows PowerShell
$env:ZHIPU_API_KEY="你的密钥"

# Linux / macOS
export ZHIPU_API_KEY=你的密钥

# 启动
python main.py
```

4. 访问 `http://localhost:5000/api/status`，看到 `zhipu` 的 `available` 为 `true` 即成功

## 三、环境变量一览

复制 `.env.example` 为 `.env` 后填写即可（`.env` 已被 `.gitignore` 排除，不会提交到仓库）。

| 变量 | 说明 |
|---|---|
| `ZHIPU_API_KEY` | 智谱密钥 |
| `MODELSCOPE_API_KEY` | 魔搭访问令牌 |
| `SILICONFLOW_API_KEY` | 硅基流动密钥 |
| `DASHSCOPE_API_KEY` | 阿里云百炼密钥（付费） |
| `LLM_BASE_URL` + `LLM_API_KEY` | 自定义 OpenAI 兼容端点，同时设置时会插到调用链最前面 |
| `LLM_MODEL` | 配合上面两项使用，指定模型名 |

**不要**把密钥写进 `config/config.json`，那里只放非敏感配置。

## 四、调整优先级与模型

编辑 `config/config.json`：

```jsonc
"llm": {
    "provider_chain": ["zhipu", "modelscope", "siliconflow", "ollama", "offline"],
    "timeout": 60,
    "max_context_messages": 20,
    "temperature": 0.7,
    "max_tokens": 4096,
    "system_prompt": "你是 Aegis……",
    "providers": {
        "zhipu": { "enabled": true, "model": "glm-4-flash" },
        "ollama": { "enabled": false, "model": "qwen2.5:7b" }
    }
}
```

- `provider_chain`：调用优先级，从左到右依次尝试，**请始终保留 `offline` 在最后**
- `enabled`：临时禁用某家，不需要删除整条配置
- `model`：换模型只改这一个字段
- `system_prompt`：角色设定，改完重启生效，不需要动代码

## 五、使用本地 Ollama（可选，真正零成本）

如果你希望完全不依赖外部服务：

```bash
# 1. 安装 Ollama（见 https://ollama.com）后拉取模型
ollama pull qwen2.5:7b

# 2. 在 config.json 中启用
#    "ollama": { "enabled": true, "model": "qwen2.5:7b" }
```

Ollama 会监听 `http://127.0.0.1:11434/v1`，无需任何密钥。
内存建议 8GB 以上，7B 模型约占用 4-5GB。

## 六、故障自检

访问 `/api/status` 可以看到每一家的实时状态：

```jsonc
{
  "chain": ["zhipu", "modelscope", "siliconflow", "offline"],
  "active": "zhipu",
  "providers": [
    { "key": "zhipu", "label": "智谱 GLM", "available": true, "reason": "" }
  ]
}
```

常见 `reason` 对照：

| 提示 | 含义 | 处理 |
|---|---|---|
| `缺少 API Key，请设置环境变量 …` | 没配密钥 | 按上文第一节配置 |
| `账户余额不足，服务已欠费` | HTTP 402 | 换免费服务商，或充值 |
| `API Key 无效或已失效` | HTTP 401 | 重新生成密钥 |
| `无访问权限（可能未完成实名认证…）` | HTTP 403 | 完成平台实名认证 |
| `请求过于频繁，已触发限流` | HTTP 429 | 降低频率，或换一家 |
| `网络不可达（…）` | 连不上服务器 | 检查网络 / 代理 / 防火墙 |

## 七、本地应答模式

当所有服务商都不可用时，系统不会抛错，而是由 `apps/llm/offline.py` 应答。
它能处理：身份介绍、问候、当前时间与日期、四则运算，其余问题会如实说明当前处于降级模式并给出排查建议。

它的定位是**保底而非替代**——保证系统永远可用、界面永远有回应，但能力远不及真正的大模型。

---

## 八、新增一家服务商

所有预设走的都是 OpenAI 兼容协议，接入新厂商只需两步：

1. 在 `apps/llm/providers.py` 的 `PRESETS` 中加一条预设（`base_url`、默认模型、环境变量名）
2. 在 `config.json` 的 `provider_chain` 与 `providers` 中引用它

无需改动任何调用逻辑。若只是临时对接，直接用 `LLM_BASE_URL` + `LLM_API_KEY` 环境变量即可，一行代码都不用改。
